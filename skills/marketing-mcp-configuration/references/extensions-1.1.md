# Standalone GetMCP Extensions 1.1.0

This reference describes local implementation, not deployment or completed real provider verification. Inspect the actual installed version/feature switches first. Do not silently replace the working bridge or change provider credentials, allowlists or gateway publication.

Authentication GETs provide presence and opaque revisions only. Preserve omitted settings and blank secrets. PATCH native servers with `authentication_revision`; advanced settings merge, `null` removes a leaf, explicit `auth_config_mode:"replace"` removes omitted values. Clear credentials only with the documented clear list. On 409, reload and review rather than overwriting a newer configuration.

Remote setup accepts URL or Paste Configuration with JSON, basic YAML/TOML, supported client-add commands and HTTPS URLs. Review mapped fields/unmapped names. Imported servers start unpublished with explicit user choices; no arbitrary command is executed. Custom-header values are encrypted/write-only; blank preserves a saved named header and deleting a row removes it. Automatic OAuth discovery/client registration needs no manually configured provider callback when supported. Fixed-client providers still need their own registration.

`GET,PUT /getmcp/v1/servers/{uuid}/provider-configuration` manages native REST providers, with `configuration_revision`, personal provider allowlist/preset and per-tool token sources. `GET,PUT /getmcp/v1/provider-tools/{id}` manages templates, annotations, noncredential headers and conservative retries with a tool revision. Management MCP uses `manage_provider_configuration`; remote header rows use existing `manage_mcp_connections`. Secrets never belong in auth_config, headers on exported tool definitions, arguments or reusable output.

WordPress-personal REST grants and existing client-driven MCP broker identities are separate. A browser connection explicitly authorizes a logged-in user/server with PKCE and one-use state; it never adopts the broker row or substitutes an operator token. Empty personal allowlists deny all, including admins; current selected-gateway membership can deliberately delegate access. Disconnect/configuration changes invalidate pending consent/cache/vault identity.

Facebook Login uses short-to-long token extension and provider expiry, followed by reconnection when needed, not a generic refresh_token grant. Instagram Page selection is encrypted per exact user/server or broker row. Discovery keeps Page access tokens private; verify granted scopes, current ownership/task and linked Instagram ID, then run a harmless conversations read. Select again to invalidate prior readiness. Activate only the three existing reviewed messaging drafts after that manager's own verification. Verify every requesting identity independently; a manager's readiness does not grant other users access. Mutations never retry automatically after an ambiguous response. Use fixtures for write tests.

The login-protected My MCP Connections portal also discovers Ads managers/children, Analytics accounts/properties, GSC properties and linked Pages. Report discovery separately from reporting. Readiness records application setup, user connection, missing/unknown scopes, expiry and harmless reads per identity. Normalized Meta results preserve nested protocol errors/content/objects; explicit account eligibility/queryability and reasons are carried in `_meta["getmcp/provider-account-readiness"]`. Unknown flags remain unknown.

Individual Meta tools can use a separate Remote MCP connection through the existing client. Discover the live catalogue, schemas/annotations and provider auth requirements; 98 tools is a historical observation. Do not publish both catalogues by accident, migrate credentials or claim real official-endpoint acceptance from synthetic checks. Current official Meta docs and a new real token extension/consent were unavailable during this development run. Google presets omit the now-ignored developer-token header; obtain Graph/Ads API versions from the installation's reviewed configuration.

Disabling the optional marketing/setup module preserves encrypted grants and blocks marked enhanced endpoints. Authentication-save protection remains active. A persistent owned MU guard survives removal; do not remove it to bypass a compatibility block. For downgrade, pause enhanced Page definitions/servers first and retain the current guard. No existing credentials are migrated and no automatic purge occurs.
